# 課程管理 Preview 驗收

本輪只推送 `preview/class-management-20261102`，不合併或推送 `main`，不執行 Production 部署。之後也先以 Preview 交付，正式發布須由使用者另行提出。

## 測試項目

- 後台 → 課程管理 → 未來課程：手機上課名、日期時間、狀態、點數、人數、地點緊湊排列。
- 「管理操作」及「上課內容」預設收合；展開後保留原有名單、地點、備課、整堂取消、內容儲存功能。
- 管理操作 → 修改時間：台灣時間，開始時間改動後預設結束時間加一小時，仍可手動修改及勾選隔天。
- 已公布、進行中及已結束課程均可修正時間；已取消課程不可修改。修改原因必填，提交前確認。
- 成功後課程、預約、候補及上課紀錄顯示時間同步更新，出席狀態及點數不變；有效預約與候補會員收到去重的站內通知。
- 重複送出相同時間修改只產生一份紀錄；另一管理畫面若已改過時間，舊畫面不能覆蓋。
- 使用測試課程驗證零人整堂取消、點數退款、體驗券退還、等待中的候補取消、重複取消不重複退款。

## 取消故障調查

使用者提供的正式站截圖：2026/11/2 12:10「空中瑜珈 Lv.0–1」，0/6 人，顯示通用伺服器錯誤。後續取得取消及優惠券核對的 Vercel 日誌，均為 `8 RESOURCE_EXHAUSTED: Quota exceeded.`，已確認是 Firestore 配額／資源限制；不是無人預約或券資料異常。尚未查閱 Firebase 用量，不能判定是每日免費額度、計費限制或短期資源限制。

取消交易保留 classId 及有效狀態的資料庫篩選，避免讀取歷史取消紀錄；保留退款資料檢查和原子交易。新增配額錯誤的 503 明確提示，避免誤判資料錯誤。錯誤回應另區分管理員設定、資料庫查詢前置條件、資料庫權限及未知錯誤，前端顯示錯誤代碼，方便對照伺服器日誌。

## 資料與部署

Preview 的程式版本不等於獨立測試資料庫。若 Preview 環境變數仍指向正式 Firebase，取消及改時間會更新同一份資料；請使用專門測試課程，不要將真實課程作為驗收資料。

本輪沒有改環境變數、Firestore rules，也沒有執行正式會員／課程資料寫入。舊的 Preview 分支缺少 Firebase 環境變數問題，仍需在 Vercel 檢查此分支的 Preview 設定。

本機使用實際 TSX、Tailwind CSS 及 Chromium 檢查 320/390/768/1280px 版面，為以假資料和操作元件替身產生的 fixture，並非正式站登入端對端測試。手機收合卡片約 172px，無水平溢位。

## 配額改善

- 每堂課的管理操作與上課內容在首次展開前不建立元件或資料監聽。
- 舊券分頁核對重用已讀取的舊會員快照；已查得的券不重複逐張讀取，只有缺券時才讀商品模板。
- 補發仍在交易內重驗管理員與會員資料；不使用分頁舊快照決定補發，保留重複發券防護。
- 配額耗盡時不自動迴圈重試、不繞過帳務驗證。這些改善不能恢復已用完的雲端額度，也未改動 Firebase 計費方案。
